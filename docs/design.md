# 🎵 Music Visualizer Player - Design Document

## 1. 产品概述

一个单页面的音乐可视化播放器，支持嵌入 YouTube/Bilibili 视频播放，同时通过 Web Audio API 生成虚拟频谱数据驱动多种 Canvas 可视化效果。

**核心设计理念：**
- 零构建依赖，单 HTML 文件即可运行
- 暗色系主题，突出可视化效果
- 响应式设计，适配桌面和移动端

---

## 2. 功能需求

### 2.1 播放器模块
- [ ] YouTube iframe 嵌入（通过 URL 参数传入视频 ID）
- [ ] Bilibili iframe 嵌入（通过 URL 参数传入 BV 号）
- [ ] 播放/暂停状态同步（通过 `postMessage` 通信）
- [ ] 进度条显示（读取 iframe 返回的时间戳）
- [ ] 音量控制（iframe 原生 API）

### 2.2 虚拟频谱生成器
- [ ] Web Audio Context 初始化
- [ ] 多振荡器叠加（3-5 个不同频率的正弦波）
- [ ] 随机噪声层（模拟真实音频的不规则性）
- [ ] 包络控制（ADSR：Attack/Decay/Sustain/Release）
- [ ] 播放状态联动（暂停时频谱衰减，播放时恢复）
- [ ] FFT 分析节点（AnalyserNode）输出 1024 点频谱数据

### 2.3 可视化效果（至少 4 种）
- [ ] **频谱柱**：经典均衡器样式，底部对齐的彩色柱状图
- [ ] **波形图**：示波器效果，连续线条显示时域波形
- [ ] **圆形频谱**：环形排列的频谱柱，中心显示专辑封面
- [ ] **粒子系统**：随节拍跳动的粒子，颜色随频率变化

### 2.4 UI 控制
- [ ] 可视化效果切换按钮（4 种效果可选）
- [ ] 主题色选择器（改变可视化效果的颜色方案）
- [ ] 灵敏度调节滑块（控制虚拟频谱的振幅范围）
- [ ] 全屏按钮（最大化 Canvas 区域）

## 4. 技术架构

### 4.1 文件结构
```
music-visualizer/
├── index.html          # 入口文件（包含所有 HTML 结构）
├── css/
│   └── style.css       # 样式表
└── js/
    ├── main.js         # 核心逻辑（播放器 + 通信）
    ├── synth.js        # 虚拟频谱生成器
    └── visualizer.js   # Canvas 可视化渲染
```

### 4.2 数据流
```
[iframe 播放器] --postMessage--> [main.js]
                                      │
                                      ▼
                              [synth.js] (生成虚拟频谱)
                                      │
                                      ▼
                              [visualizer.js] (Canvas 渲染)
                                      │
                                      ▼
                                [Canvas 2D Context]
```

### 4.3 关键技术点

**iframe 通信协议：**
```javascript
// 发送消息给 iframe（控制播放/暂停）
player.postMessage('{"event":"command","func":"playVideo","args":""}', '*');

// 接收 iframe 消息（获取播放状态/时间戳）
window.addEventListener('message', (e) => {
  if (e.data.event === 'ready') { /* 播放器就绪 */ }
  if (e.data.event === 'stateChange') { /* 播放状态变化 */ }
  if (e.data.event === 'ping') { /* 心跳包，包含当前时间戳 */ }
});
```

**虚拟频谱算法伪代码：**
```
function generateVirtualSpectrum(time, isPlaying):
  // 基础振荡器（模拟低频鼓点）
  bass = sin(time * 2π * 2) * envelope(time)
  
  // 中频层（模拟人声/乐器）
  mid = sin(time * 2π * 8) * random(0.3, 0.7)
  
  // 高频层（模拟镲片/噪音）
  high = whiteNoise() * random(0.1, 0.3)
  
  // 混合三层
  signal = bass * 0.5 + mid * 0.3 + high * 0.2
  
  // 通过 FFT 转为频域数据
  return FFT(signal, 1024)
```

## 5. 可视化效果详细设计

### 5.1 频谱柱（Bar Spectrum）
- 128 根垂直柱，从左到右对应低频到高频
- 颜色渐变：底部红色 → 中部黄色 → 顶部青色
- 柱宽 4px，间距 2px
- 带镜像效果（上下对称）

### 5.2 波形图（Waveform）
- 单条连续线条，宽度 = Canvas 宽度
- 线条颜色：accent 色
- 带辉光效果（shadowBlur = 10）
- 平滑插值（贝塞尔曲线连接采样点）

### 5.3 圆形频谱（Circular）
- 中心圆显示专辑封面（或默认图标）
- 频谱柱沿圆周放射状排列
- 柱子长度随频率振幅变化
- 缓慢旋转动画（0.5°/帧）

### 5.4 粒子系统（Particles）
- 200 个粒子，位置随机分布
- 粒子速度受频谱振幅驱动
- 颜色随频率映射（低频=红，高频=蓝）
- 重力效果（粒子向上飘然后下落）

## 7. 响应式设计

- **桌面端（>1024px）**：完整布局，iframe 最大宽度 800px
- **平板端（600-1024px）**：iframe 宽度 100%，控制栏横向滚动
- **移动端（<600px）**：iframe 在上，Canvas 在下，控制栏折叠为汉堡菜单

---

## 8. 性能考量

- Canvas 使用 `requestAnimationFrame` 而非 `setInterval`
- 粒子数量上限 200（移动端降至 100）
- FFT 数据复用，不每帧重新计算
- 离屏 Canvas 缓存静态元素（如背景渐变）

## 10. 风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|----------|
| YouTube API 变更导致通信失败 | 无法获取播放状态 | 降级为纯本地播放模式 |
| 移动端 Canvas 性能不足 | 帧率下降 | 减少粒子数量，降低分辨率 |
| 浏览器不支持 Web Audio API | 无法生成频谱 | 使用预生成的频谱数据作为 fallback |
